# 社区物业管理与报修系统

> 面向住宅小区的物业综合管理平台：业主在线报修、物业派单维修、物业费批量计费与收缴、车位/公告/访客一站式管理。
> 设计风格为**温馨社区风**（暖橙 `#ea580c` + 浅绿 `#65a30d` + 米白），圆润卡片与亲和力界面。

---

## 四、启动步骤

### 前置条件
- Python 3.11（Anaconda base 环境，已安装 Django 5.2.10 / PyMySQL 1.2.0 / PyJWT 2.4.0 / openpyxl 3.0.10）
- Node.js v24 + npm（用于构建前端）
- MySQL 已启动，并准备好具有 `property_management` 数据库权限的本地账号

### 1. 初始化数据库（每次重置数据都执行一次）
```bash
cd db
mysql -uroot -p --default-character-set=utf8mb4 < init.sql
```
脚本开头会 `DROP DATABASE IF EXISTS property_management; CREATE DATABASE ...`，**可重复执行**，末尾会打印各表数据条数。

### 2. 构建前端（产物输出到 `backend/static`，由 Django 托管）
```bash
cd frontend
npm install
npm run build
```

### 3. 启动后端（单端口访问）
先参考根目录 `.env.example` 设置数据库密码和签名密钥。PowerShell 示例：

```powershell
$env:PROPERTY_DB_PASSWORD="请填写本机数据库密码"
$env:PROPERTY_DJANGO_SECRET_KEY="请替换为随机字符串"
$env:PROPERTY_JWT_SECRET="请替换为至少 32 位的随机字符串"
```

```bash
cd backend
python manage.py runserver 0.0.0.0:8004 --noreload
```

### 4. 访问系统
浏览器打开 **http://localhost:8004/**（前端为 hash 路由，刷新不会 404）

### 一键启动 / 停止（Windows）
```bat
start.bat   :: 前端未构建时自动 npm install + build，然后启动 Django
stop.bat    :: 按端口 8004 精确杀进程（PID 去重），并校验端口已释放
```

## 六、项目特色功能说明

### 1. 报修工单状态机（服务端强校验）

状态集合与合法流转（定义于 `backend/apps/core/utils.py` 的 `TRANSITIONS`）：

```
待受理 ──派单──> 已派单 ──开始处理──> 处理中 ──完成维修──> 已完成 ──业主评价──> 已评价
   │                │
   ├──驳回──> 已驳回  └──取消──> 已取消
   └──取消──> 已取消
```

- `已评价`、`已驳回`、`已取消` 为**终态**，不可再流转。
- 每一次流转都必须先通过 `can_transition(当前状态, 目标状态)` 校验，不合法则返回中文提示并**不写库**，例如：
  - `待受理 → 已完成` → `非法状态流转：工单当前为「待受理」，不能直接变更为「已完成」，当前允许的流转为：已派单、已驳回、已取消`
  - `已评价 → 处理中` → `工单已处于终态「已评价」，不能再变更为「处理中」`
  - `已完成 → 已派单` → `非法状态流转：工单当前为「已完成」，不能直接变更为「已派单」，当前允许的流转为：已评价`
- 前端详情页用 `el-steps` 步骤条展示流转进度，并将「可执行操作」按当前状态动态渲染（不可执行的操作按钮不出现）。
- 每次流转都会写入 `repair_record`，形成可追溯的处理时间线。
- 角色约束：派单/驳回仅管理员；开始处理/完成维修仅管理员与物业员工（且员工只能操作指派给自己的工单）；评价仅报修业主本人。

### 2. 超时提醒（> 24 小时未受理）

- 规则：工单处于 `待受理` 且 `NOW() - submit_time ≥ 24 小时` → `timeout_flag = 1`。
- 实现：`refresh_timeout_flags()` 在工单列表/我的工单查询前执行，批量刷新超时标记（已受理的自动清除标记）；`RepairOrder.to_dict()` 另做一次实时判断，保证展示值始终准确。
- 演示数据中 3 条超时工单（提交于 26~30 小时前），列表中显示红色「超时」标签，首页与统计页有「超时未受理」计数卡片与「只看超时」筛选。

### 3. 物业费批量生成的去重逻辑

**计费公式**：`应缴金额 = 房屋建筑面积 × 单价(元/㎡/月) × 计费月数`（默认单价 2.50，四舍五入保留 2 位小数）

管理员选择「楼栋 + 账期（YYYY-MM）+ 单价 + 月数」后可**先预览再见账单**：
- 预览接口 `GET /api/bill/preview` 返回该楼栋全部房屋的逐户金额，并标注每户是「待生成」还是「已存在(跳过)」，同时给出 `将新生成 / 已存在跳过 / 预计新增金额` 汇总。
- 生成接口 `POST /api/bill/generate` 的去重分三层保障：
  1. **生成前查重**：一次性查出该楼栋该账期已存在的 `room_id` 集合，循环中直接跳过并计入 `skipped`；
  2. **数据库唯一键兜底**：`fee_bill` 上建立 `UNIQUE KEY uk_bill_room_period (room_id, fee_type, period)`，即使并发也不会写重；
  3. **异常兜底**：捕获 `IntegrityError` 后计入 `skipped`，不中断整批生成。
- 返回 `{created, skipped, totalRooms, totalAmount, batchNo}`，每次生成写入唯一批次号
  `BATCH-{账期}-{楼栋}-{YYYYmmddHHMMSS}{毫秒3位}-{随机4位}`（例 `BATCH-2026-10-B04-20260925005522123-a1b2`）；
  毫秒 + 随机后缀保证**同一秒内连续调用也不会重号**，便于追溯。
- 实测：对 4 号楼 2026-10 连续执行两次批量生成，第一次 `新增 24 条 / 跳过 0 条`，第二次 `新增 0 条 / 跳过 24 条`，数据库账单条数与金额完全不变。

### 4. 滞纳金计算

```
滞纳金 = 逾期天数 × 日滞纳金率 × 欠费金额
逾期天数 = max(0, 今天 - 缴费截止日)        （已缴清账单为 0）
欠费金额 = 应缴金额 - 已缴金额
日滞纳金率 = 0.0005（即 0.05%/日，常量 LATE_FEE_RATE）
```

- 账单 `due_date` 取账期当月最后一天（由 `period_due_date()` 计算）。
- `calc_late_fee()` 在查询时实时计算，避免存量数据过期；欠费统计接口会把最新滞纳金回写 `late_fee` 字段。
- 账单详情接口额外返回可读公式串，例如：
  `滞纳金 = 逾期天数(56) × 日滞纳金率(0.0005) × 欠费金额(192.0) = 5.38 元`
- **本次应缴合计 = 应缴金额 + 滞纳金 - 已缴金额**，缴费金额超过应缴合计会被拒绝（提示具体可缴金额）。
- 实测：账单 `WY20260700007`（面积 76.8㎡ → 应缴 192.00 元，截止 2026-07-31，未缴），2026-09-25 查询逾期 56 天，
  人工计算 `192.00 × 0.0005 × 56 = 5.376 ≈ 5.38`，与接口返回 `5.38` 完全一致。

### 6. 其他实现要点

- **统一响应体**：`{ code, msg, data }`；401/403 使用对应 HTTP 状态码，业务异常返回 HTTP 200 + `code=500`，前端拦截器统一提示。
- **鉴权**：JWT（PyJWT HS256，24 小时有效），除登录外所有接口均需 `Authorization: Bearer {token}`。
- **图片上传**：校验扩展名 + **文件头魔数**（jpg/png/gif/webp），伪装成图片的文本文件会被拒绝；单张限制 5MB。
- **Excel 导出**：openpyxl 生成真实 `.xlsx`，表头橙底白字、冻结首行、列宽自适应，中文文件名用 RFC 5987 编码。
- **前端静态资源**：`vite.config.js` 使用 `base: '/static/'`（与 Django `STATIC_URL` 一致），`build.outDir` 指向 `../backend/static`，构建后由 Django 单端口托管。

```
03-property-management/
├── README.md
├── start.bat / stop.bat
├── db/
│   └── init.sql                 # 建库建表 + 中文演示数据（可重复执行）
├── backend/
│   ├── manage.py
│   ├── requirements.txt
│   ├── config/                  # settings.py / urls.py / wsgi.py
│   ├── apps/core/               # models / utils（状态机、滞纳金）/ views_* / urls
│   ├── media/uploads/           # 上传的报修与处理照片
│   └── static/                  # 前端构建产物（Django 托管），index.html 即 SPA 入口
└── frontend/
    ├── package.json
    ├── vite.config.js
    └── src/                     # api / router / store / components / layout / views
```
